# Spec — garde-deps v2 (contrôle non contournable par l'IA)
Statut : livrée

## 1. Objectif
Fermer les contournements de garde-deps par l'agent (Edit/Write direct sur un manifeste, script exécuté, `python -c`, retouche des hooks/réglages). Le hook Bash reste un filtre rapide ; la barrière devient le **contrôle par résultat** (diff des manifestes et lockfiles), appliqué localement (PostToolUse, Stop) et surtout en CI côté serveur. L'utilisateur garde une échappatoire, `.garde-deps-exceptions`, que l'IA ne peut pas faire valoir seule.

## 2. Hors périmètre
- Aucune dépendance (stdlib ; `tomllib` impose Python ≥ 3.11 : runner 3.12, devbox 3.13). `garde-git.py` et `rappel-clear.py` inchangés. `~/.claude/settings.json` n'est **pas** modifié par le codeur (l'utilisateur applique l'étape 15).
- Autres manifestes (`setup.py`, `Pipfile`, `go.mod`, `Gemfile`, `deno.json`…), npm `package-lock.json` v1, cache de résultats.
- Contournements locaux résiduels assumés (la CI les rattrape) : chemin protégé obfusqué (variable, base64, `cd` puis nom court), script écrit puis exécuté qui touche un chemin protégé, déplacement local de `main` (`git branch -f main`) pour vider le diff.
- Réutilisation de la CI dans d'autres dépôts (documentée plus tard).

## 3. Fichiers
- `hooks/deps_communs.py` — créer — code commun extrait de `garde-deps.py` (réseau, registres, licences, `examine`), + exceptions, OSV par lot, chemins protégés (L2-L3, L5).
- `hooks/garde-deps.py` — modifier — correctifs du parseur (L1), import de `deps_communs` (L2), exceptions (L3), chemins protégés (L5).
- `hooks/verifie-manifestes.py` — créer — contrôle par résultat, modes hook/CLI/CI (L2-L4).
- `hooks/hooks.json` — modifier — PostToolUse, Stop, SubagentStop (L2) ; matcher de garde-deps élargi (L5).
- `tests/test_hooks.sh` — modifier — cas L1 et L5, appel de `test_manifestes.sh`. `tests/test_manifestes.sh` — créer (L2-L4). `tests/fixtures/garde-deps.json` — modifier — paquets `trou` npm/pypi avec faille (L2).
- `agents/relecteur.md` — modifier — puce « Dépendances » réécrite, puce « Exceptions » (L3).
- `.github/workflows/tests.yml` — modifier — job `deps` (L4).
- `README.md`, `CHANGELOG.md` — modifier — doc, verrouillage, entrée 0.3.0 (L5).

## 4. Étapes
1. (L1) `jetons` : plus de `replace("\n", " ; ")` ; `shlex.shlex(cmd, posix=True, punctuation_chars=";&|()<>\n")`, `lex.whitespace = " \t\r"`, `lex.commenters = ""` ; `separateur` accepte `\n`. Nouvelle fonction `sans_commentaires(s)` appliquée dans `analyse` juste après `retire_heredocs` : hors apostrophes/guillemets et non échappé, un `#` en début de mot (début de chaîne, après blanc, `\n` ou l'un de `;&|()<>`) supprime jusqu'au `\n` exclu. `sans_commentaires` empile des cadres (comme `premier_heredoc`) : un `$( … )` imbriqué dans des guillemets doubles est du code, donc `echo "$(echo "a #")"; npm i x` n'est pas tronqué au `#`. `premier_heredoc` saute les commentaires selon la même règle (sinon `ls # <<EOF` cache les lignes suivantes).
2. (L1) `decoupe` : un jeton de redirection qui commence par des caractères de `;|()` ou par `&&` (ex. `;>`, `&&>`) clôt le segment ; le reste du jeton est traité comme redirection. `module_python` saute la valeur de `-X` et `-W` (formes séparées). `paquets` : `yarn global add` (args = `toks[3:]`).
3. (L1) Tests (bloqués, code 2) : `ls # c⏎npm i gpl-pkg`, `echo a#b; npm i gpl-pkg`, `curl https://x/a#frag && npm i gpl-pkg`, `cat <<EOF | bash⏎# setup⏎npm i gpl-pkg⏎EOF`, `ls # <<EOF⏎npm i gpl-pkg⏎EOF`, `true;>log npm i gpl-pkg`, `python3 -X utf8 -m pip install gpl-pkg`, `python3 -W ignore -m pip install gpl-pkg`, `yarn global add gpl-pkg` (⏎ = `$'\n'`). Passent (0, muet) : `ls #c && npm i gpl-pkg`, `echo $# && cargo add bon`.
4. (L2) `deps_communs.py` : y déplacer sans changement de comportement `UA … ALIAS`, `recupere`, `cle`, `licence_npm`, `charge`, `niveau_id`, `niveau`, `aujourdhui`, `examine`, `SEMVER`, `exacte`, et une fonction `pep508(t) -> (nom normalisé, version exacte|None)` extraite de `paquets`. `garde-deps.py` fait `sys.path.insert(0, dirname(abspath(__file__)))` puis `from deps_communs import *` ; aucune duplication. Ajouts : `examine(…, strict=False)` (strict : « vérification impossible » va dans `blocs`) ; `BUDGET` modifiable ; `osv_lot([(registre, nom, version)])` = un POST `https://api.osv.dev/v1/querybatch` (`{"queries":[…]}` → `results[i].vulns[].id`), en fixtures lit les clés `osv-<registre>-<nom>`.
5. (L2) `verifie-manifestes.py [--depot DIR] [--base REF] [--cible REF] [--hook post|stop] [--ci]`. Manifestes : `Cargo.toml`, `package.json`, `pyproject.toml`, `requirements*.txt` et `requirements/*.txt` ; lockfiles : `Cargo.lock`, `package-lock.json` (v2/v3), `pnpm-lock.yaml`, `yarn.lock`, `uv.lock`, `poetry.lock` ; chemins sous `node_modules/ target/ .venv/ vendor/` ignorés. Base par défaut : `git merge-base HEAD origin/main`, sinon `main`, sinon `master`, sinon `HEAD` (arbre vide si aucun commit) ; cible par défaut : arbre de travail. Fichiers touchés = `git diff --name-only <base> [<cible>]` + (sans `--cible`) `git ls-files -o --exclude-standard`, filtrés par nom : **aucun → `exit 0` immédiat, sans réseau**. Hors dépôt git → `exit 0`. Contenu base/cible : `git show <ref>:<chemin>` (absent = vide) ou lecture du fichier.
6. (L2) Extraction (`tomllib`, `json`, regex ; erreur de lecture d'un fichier ou d'un lockfile = avertissement `<chemin> illisible`, en `--ci` blocage ; l'erreur d'un lockfile est gardée en cache et reportée à chaque appel) :
   - Cargo.toml : `[dependencies]`, `[dev-dependencies]`, `[build-dependencies]`, `[target.*.…]`, `[workspace.dependencies]` ; chaîne ou table (`version`, `package` = vrai nom) ; `git` et `path` hors dépôt sont des dépendances hors registre (voir plus bas), `path` interne et `workspace = true` ignorés. Cargo.lock / uv.lock / poetry.lock : `[[package]]` `name`/`version`, ignorés si `source` n'est pas un registre.
   - package.json : `dependencies`, `devDependencies`, `optionalDependencies`, `peerDependencies` ; `npm:vrai@spec` → vrai nom ; hors registre : `github:`/`git+`/URL/`user/repo`, `file:`/`link:` sortant du dépôt ; ignorés : `workspace:`, `file:` interne, autres valeurs avec `:` ou `/`. package-lock : `packages`, nom = après le dernier `node_modules/`, sans `link`. pnpm-lock : clés à 2 espaces sous `packages:` (`/nom@v` ou `nom@v`, scope et guillemets gérés). yarn.lock : en-têtes en colonne 0 (hors `#`, `__metadata`, protocoles `workspace: patch: file: link: portal: git http`), nom = avant le dernier `@`, version = ligne `version "x"` ou `version: x`.
   - pyproject : `[project] dependencies`, `[project.optional-dependencies]`, `[dependency-groups]` (chaînes seules), `[tool.poetry(.group.*).dependencies]` (hors `python`). `[tool.uv.sources]` et `git`/`url`/`path` poetry : hors registre. requirements : une ligne PEP 508 (`pep508`), ignorés options `-…` (sauf `-e` et `-r`/`-c`, dont les fichiers inclus sont suivis récursivement sans boucle, relatifs au fichier incluant), commentaires ; URL, `git+`, `nom @ url` et chemins hors dépôt = hors registre.
7. (L2) Classement. **Directs** = paquets d'un manifeste de la cible dont (spec, version résolue) diffère de la base ou est absent de la base ; version examinée = version résolue par le lockfile du même dossier ou du plus proche parent (unique), sinon `exacte(spec)`/`==`, sinon dernière ; règles complètes via `examine`, **bloquants**. **Transitifs** = couples (nom, version) des lockfiles de la cible absents de la base, hors directs, au plus 1000 : `osv_lot` seul, failles en **avertissement** (licence/âge non examinés : trop de requêtes). Suppressions ignorées. **Hors registre** (git, URL, chemins sortant du dépôt) : avertissement `<registre> <nom> (<chemin>) : dépendance hors registre, à valider (<source>)` en local, blocage en `--ci`, sauf exception de `.garde-deps-exceptions` (version `*` ou la source exacte) ; seules les sources ajoutées ou modifiées par rapport à la base sont signalées.
8. (L2) Sortie CLI : blocages sur stderr `⛔ Bloqué par garde-deps (manifestes) :` puis `- <registre> <nom>@<v> (<chemin>) : <raison>`, `exit 2` ; avertissements `⚠ …` sur stdout, `exit 0`. `--hook post` (stdin JSON, `cwd` = dépôt) : si `tool_name` ≠ Bash et que le nom de `tool_input.file_path` n'est ni manifeste ni lockfile → `exit 0` sans git ; si le hash du diff des manifestes égale celui de `$(git rev-parse --git-dir)/garde-deps-etat` → `exit 0` (déjà signalé), sinon l'y écrire puis contrôler ; avertissements en JSON `systemMessage` + `additionalContext` (`hookEventName: PostToolUse`). `--hook stop` : blocage → stderr + `exit 2` ; si `stop_hook_active` est vrai → JSON `{"systemMessage": "⚠ garde-deps : paquet non conforme encore présent : …"}`, `exit 0` (évite la boucle, l'utilisateur est prévenu). En mode hook, exception imprévue → `exit 0`.
9. (L2) `hooks.json` : `PostToolUse` matcher `Edit|Write|MultiEdit|Bash` → `verifie-manifestes.py --hook post` ; `Stop` et `SubagentStop` (sans matcher) → `--hook stop` ; timeouts 30, sans `onFailure`.
10. (L3) `.garde-deps-exceptions` (racine du dépôt) : lignes `<registre> <nom> <version|*> <AAAA-MM-JJ> <raison…>`, `#` = commentaire, ligne invalide = avertissement. Dans `examine`, un paquet couvert voit ses blocages passer en avertissements suffixés `(exception du <date> : <raison>)`. Lu par `verifie-manifestes.py` (fichier de la cible) et par `garde-deps.py` (remonte de `cwd` jusqu'au dossier contenant `.git`).
11. (L3) `relecteur.md` : la puce « Dépendances » devient : lancer `python3 "$V" --base main` avec `V` = dernier `~/.claude/plugins/cache/kit-perso/kit-perso/*/hooks/verifie-manifestes.py` (`sort -V | tail -1` ; dans kit-perso : `hooks/verifie-manifestes.py`) ; code 2 = bloquant, `⚠` = mineur, script introuvable = mineur « dépendances non vérifiées » ; règles listées comme avant. Nouvelle puce « Exceptions » : toute ligne ajoutée à `.garde-deps-exceptions` ou tout changement sous `.github/workflows/` est **bloquant** « à valider par l'utilisateur », citée en clair (on ne se fie pas à l'auteur du commit : falsifiable).
12. (L4) Mode `--ci` : strict (injoignable, fichier illisible, exception imprévue → blocage, traceback sur stderr ; justification : c'est la barrière, l'IA n'agit pas sur le réseau du runner, une relance coûte peu), `DELAI` 10 s, `BUDGET` 120 s. Exceptions lues **dans la base seulement** ; les lignes ajoutées par la cible sont listées « non appliquées tant qu'elles ne sont pas sur main ». Si `GITHUB_STEP_SUMMARY` est défini, y écrire en Markdown : paquets examinés, blocages, avertissements, exceptions ajoutées, fichiers modifiés sous `.github/workflows/` ou nommés `.garde-deps-exceptions`.
13. (L4) `tests.yml` : ajouter le déclencheur `pull_request_target:` ; job `hooks` : `if: github.event_name != 'pull_request_target'` ; nouveau job `deps` (`if: github.event_name == 'pull_request_target'`, ubuntu-24.04, 5 min, `permissions: contents: read`) : checkout de la base (même SHA épinglé, `persist-credentials: false`) = script de confiance ; 2e checkout `ref: ${{ github.event.pull_request.head.sha }}`, `path: pr`, `fetch-depth: 0`, `persist-credentials: false` ; `run: python3 hooks/verifie-manifestes.py --ci --depot pr --base "$BASE" --cible HEAD` avec `env: BASE: ${{ github.event.pull_request.base.sha }}`. Justification : `pull_request_target` exécute le workflow de `main`, la PR ne peut donc ni modifier ni retirer la barrière ; aucun code de la PR n'est exécuté (lecture git seulement). Le job ne tourne qu'une fois fusionné dans `main`.

Lecteurs (`cat grep git diff`, `echo` sans redirection, `git commit -m`…) passent. `hooks.json` : matcher de garde-deps → `Bash|Edit|Write|MultiEdit|NotebookEdit`. garde-git n'est pas modifié (le parseur de garde-deps est plus complet).

## 6. Tests
```
bash tests/test_hooks.sh && bash tests/test_manifestes.sh && python3 -m py_compile hooks/*.py && claude plugin validate --strict .
```
`test_manifestes.sh` crée des dépôts jetables (`mktemp -d`, `git init -q -b main`, `git -c user.name=t -c user.email=t@t commit`), avec `GARDE_DEPS_FIXTURES` (et `/nonexistent` pour prouver l'absence de lookup), libellés `verifie-manifestes …`, et sort en 1 si un cas échoue ; `test_hooks.sh` l'appelle à la fin.

## 7. Décisions (questions ouvertes tranchées par l'utilisateur)
1. Transitifs : avertissement seulement (OSV seul).
2. Exceptions lues en CI uniquement depuis `main` (base).
3. Job `deps` en `pull_request_target`, sans exécuter de code de la PR (manifestes lus comme données).
4. Check obligatoire sur `main` : réglage manuel de l'utilisateur, documenté dans le README.
5. Bac à sable Bash de Claude Code : hors périmètre, mentionné dans le README comme piste.
6. `garde-git.py` inchangé.
7. Tout dans la PR #3 (L6 fusionné dans L5).
